# 無文字 UI 規範 UI_NO_TEXT（2026-10-17）

> 作者：首席遊戲設計兼 UI 設計（子代理）。回應 HSU v0.2 回饋第 2–5、7 點。
> **硬性規則：遊戲畫面上不出現任何文字（中文、英文都不行），只保留數字和 × + − = / % 這幾個數學符號。**
> 例外：設定選單的語言名稱、Steam 成就名稱、商店頁。這些都不在遊戲畫面內。
> 標記：**假設** = 推理未驗證。

## 1. 研究：真人設計、少文字也能懂的 UI

| 遊戲 | 做法 | 我們學什麼 | 來源 |
|---|---|---|---|
| Mini Metro | 車站用高對比的**形狀**辨識；乘客用同一個形狀（較小、無外框）表示要去哪；背景地理是低對比，退到後面；次要資訊推到畫面邊緣；未取得的東西用小灰點 | 一個形狀只代表一件事，而且到處重用；遊戲區之外的 UI 退到邊緣、低對比 | [Mechanics of Magic：Mini Metro 視覺設計](https://mechanicsofmagic.com/2023/04/22/visual-design-of-games-mini-metro/)；[GDC 2017 Less is More](https://www.gamedeveloper.com/design/attend-gdc-2017-and-learn-the-value-of-less-is-more-from-a-i-mini-metro-i-dev) |
| Limbo／Inside | 用**可供性**暗示規則（把手 = 可以拉）；學會一個例子就能推到同類；第一次遇到時失敗代價低；教學時移除干擾；可互動物件要明顯看得出可互動；避免藏起來或延遲的提示 | 第 1 回合只給教學需要的東西；可以點的東西一定要長得「可以點」 | [Game Developer：Limbo 關卡設計分析](https://gamedeveloper.com/design/design-bits-analysis-limbo-s-level-design---mostly-perfect)；[GDC Europe：Carlsen 談 Limbo](https://www.gamedeveloper.com/game-platforms/gdc-europe-i-limbo-i-s-carlsen-on-making-players-your-worst-enemy-and-your-best-friend) |
| Balatro | 分數**按計算順序**逐步出現：籌碼先數（藍）、倍率接手（紅）；觸發的小丑由左到右依序跳一下；數字像拉霸滾輪滾動、帶一點回彈；震動強度跟分數大小走；每張計分的牌音高遞升 | 計算順序 = 動畫順序；「基礎分」和「倍率」各用一個固定顏色；聲音音高告訴你「還在加」 | [Blake Crosley：Balatro 的回饋設計](https://blakecrosley.com/zh-Hant/guides/design/balatro)（數值是作者的示意，不是遊戲原始碼） |
| Baba Is You | 規則本身就是場景中的物件；第一關只有一種可能的動作，玩家靠推動實驗學會 | 教學關卡的手牌與杯子要設計成「只能做對的事」 | [Steam 討論：Baba Is You 教學](https://steamcommunity.com/app/736260/discussions/0/1647665620937292845) |
| Islanders | 放建築前，游標旁直接顯示放在這裡會得幾分，範圍內每個鄰居各自顯示 + 或 − | **倒之前就預覽**：在杯子上直接畫出會發生的反應 | [Wikipedia：Islanders](https://en.wikipedia.org/wiki/Islanders_(video_game)) |

### 歸納出 8 條原則
1. **一個形狀 = 一個意思**，全遊戲重用（材料圖示出現在瓶身、預覽、結算、圖鑑都是同一個）。
2. **形狀先於顏色**：每個材料都有獨特輪廓，色盲也能分。
3. **行動之前就預覽**（Islanders）：拖曳時畫出結果，而不是事後解釋。
4. **計算順序就是動畫順序**（Balatro）：基礎分 → 倍率 → 乘起來 → 流進受器。
5. **可互動的東西要會動**：可以點的部位 hover 時晃動或抬起；不能點的東西永遠不動。
6. **教學靠限制**（Limbo、Baba）：第一回合只給做得出好結果的手牌，安全失敗。
7. **次要資訊推到邊緣、低對比**（Mini Metro）：杯子是唯一的主角。
8. **聲音也是 UI**：音高遞升表示「還在加」，低音表示「過線了」。

## 2. 圖形語言

### 2.1 材料（瓶身圖示、粒子、預覽共用）
每種材料有：**瓶身形狀**（輪廓）＋**符號**（瓶上的刻印，16×16 可辨識）＋**底色**（銅版畫手工上色色票）＋**粒子紋理**（刻線方向）。

| 材料 | 瓶身形狀 | 符號 | 底色 | 粒子紋理 |
|---|---|---|---|---|
| 沙 | 矮胖袋 | 三個點堆成三角 | 赭黃 | 點刻 |
| 水 | 圓底瓶 | 一道波浪 | 靛藍 | 水平細線 |
| 油 | 細頸長瓶 | 一滴水滴＋橫線 | 琥珀 | 斜線 |
| 熔岩 | 陶罐 | 向上的三道裂紋 | 朱紅 | 交叉線＋亮點 |
| 酸 | 方形瓶 | 一個被咬缺的圓 | 黃綠 | 波點 |
| 火藥 | 小桶 | 星形 | 炭灰 | 粗點 |
| 冰 | 六角瓶 | 六角雪花 | 淡青 | 交錯格 |
| 種子 | 布袋 | 一顆芽 | 草綠 | 小橢圓 |
| 火星 | 小錫盒 | 火花（4 道短線） | 橘 | 單點閃爍 |
| 硫磺 | 扁瓶 | 三角＋十字（煉金術的硫符號） | 硫黃 | 菱形網 |
| 泥（杯底） | 不出現在手牌 | 兩道下沉的弧線 | 褐 | 橫向粗線 |
| 生成物（石、玻璃、蒸氣、煙、植物） | 不出現在手牌 | 各有符號，只在預覽和結算中出現 | 依物質 | 依物質 |

規則：瓶身輪廓兩兩不同；符號使用統一的筆寬（1.5px @16px），與銅版畫刻線同粗；顏色只有手工上色的 10 色，飽和度最高的顏色保留給**金**與**火**。

### 2.2 反應圖示
反應用「**兩個輸入符號相撞 → 一個結果符號**」的小象形表示，例：水符號 + 熔岩符號 → 石塊符號＋一朵蒸氣。
- 在預覽和結算中，反應只顯示**結果符號**（16px）加上方一個小的元素點。
- 第一次發生某反應時，會播放一次完整的「相撞」小動畫（約 0.6 秒），之後只顯示結果符號。這就是不用文字的教學：玩家看過一次就記得。
- 元素點：火 = 向上三角、水 = 向下三角、土 = 有橫線的向下三角、氣 = 有橫線的向上三角（煉金術四元素符號，本身就是幾何形狀）。

### 2.3 分數、倍率、目標
| 資訊 | 呈現 |
|---|---|
| 基礎分 | 就地彈出的數字，**墨黑**，跟著反應位置浮起 |
| 倍率 | 杯子右側四個元素符號，點亮幾個就亮幾個；下方 `×5` 的數字用**朱紅** |
| 一倒的總分 | 基礎分數字飛向右側、和 ×倍率相撞、合成一個**金色**數字，接著化成金砂 |
| 目標 | 受器（右下的玻璃瓶）上的金線，金砂高度就是進度；金線旁有目標數字 |
| 回合 | 頂端一排小圓點，目前回合是實心 |
| 幕 | 頂端 4 個色點（黑白黃紅），目前的一個較大 |
| 剩餘倒數 | 手牌下方一排小瓶剪影，用掉一個暗一個 |
| 火柴 | 火柴棒圖示，幾根就畫幾根 |
| 錢 | 金幣圖示 + 數字 |
| 壓力 | 蓋子上的錶，指針轉向紅區 |

### 2.4 按鈕（只用圖示）
| 功能 | 圖示 | 說明 |
|---|---|---|
| 點火柴 | 一根火柴 | 點一下進入「點火模式」，游標變成火柴 |
| 蓋／開蓋子 | 蓋子 | 蓋上時圖示是蓋著的 |
| 結束回合 | 沙漏倒過來 | 只有在還有剩餘倒數時出現 |
| 離開商店 | 門＋向右箭頭 | |
| 重骰商店 | 兩道彎曲的箭頭 | 旁邊是價錢數字 |
| 暫停／設定 | 齒輪 | |
| 圖鑑 | 一本打開的書 | |
| 重玩教學動畫 | 眼睛 | |

按鈕的規則：每個按鈕至少 44×44px（手機觸控）；可以按的時候有完整的刻線與底色，不能按的時候只剩淡色輪廓。

### 2.5 無字教學（第 1 回合）
用**示範動畫 + 手勢提示 + ghost 預覽**，分三拍。每一拍在玩家做對之後才進到下一拍，沒有「下一步」按鈕。

1. **倒**：一隻半透明的手（銅版畫風格的手，不是 emoji）把水瓶從手牌拖到杯子上方，杯中出現半透明的落點柱，手放開，水流下去。動畫循環播放，直到玩家自己拖出第一瓶。手牌只有水和熔岩。
2. **反應**：玩家拿起熔岩時，杯中水面上直接浮出「石塊＋蒸氣」的結果符號（ghost 預覽，見 §3）。熔岩倒下去，真的出現那兩個符號，第一次的相撞動畫播放一次。
3. **點火**：第 2 倒的手牌只有油和火柴。油倒完之後，火柴圖示開始輕微晃動，示範手把火柴拖到油上。點下去後，第一筆金砂流進受器，金線閃一下。

教學中沒有失敗：前兩倒保證會過第 1 回合金線。**假設**：示範手在玩家 4 秒沒有動作後才出現，避免干擾已經懂的人。

## 3. 互動回饋

### 3.1 hover／拖曳預覽（最重要）
- **拖曳瓶子到杯子上方時**：
  - 杯中畫出半透明的**落點柱**（寬度 = 倒料寬度），直到它碰到的第一層材料。
  - 在接觸面上方，浮出**會發生的反應結果符號**（最多 3 個），每個符號旁一個淡色的估計基礎分數字。預覽來源：查詢落點柱下方 3 列內的材料，套用反應表。不做完整模擬，所以是「會碰到什麼」而不是精確分數。
  - 這一瓶如果會點亮新的元素，右側對應的元素符號會先預亮（虛線外框）。
- **拿著火柴移到杯上時**：會被點燃的格子以暖色輪廓閃爍，範圍圈跟著游標；如果範圍內有火藥，顯示爆炸符號。
- **蓋子**：hover 時壓力錶的指針預先跳到「如果現在蓋上，3 秒後的壓力」位置（虛線指針）。
- **商店的瓶性、符文**：拖到瓶或刻點上時，目標會放大並顯示效果的小動畫（例：永燃拖到油瓶上，瓶裡的油燒起一小團火）。

### 3.2 可互動物件的提示
- 可以拖的東西（手牌、商店物品、符文）：靜止時偶爾（每 4–6 秒，隨機錯開）輕輕晃一下，hover 時抬起 8px。
- 可以點的東西（火柴、蓋子、閥門）：hover 時圖示的線條變粗 1px，游標下方出現一個小圓圈。
- 不能互動的東西：永遠不動。

### 3.3 動畫時機
| 事件 | 時長 | 曲線 | 備註 |
|---|---|---|---|
| hover 抬起 | 120ms | 帶回彈（overshoot） | |
| 拖曳中的瓶子 | 跟手，延遲 1 幀 | — | 傾斜角度跟水平速度連動 |
| 反應符號浮起 | 400ms 浮起，停 600ms，再淡出 300ms | ease-out | 同一位置的同種反應合併成一個數字並往上加 |
| 基礎分飛向倍率 | 350ms | ease-in | 多筆時每筆錯開 60ms，音高逐筆升半音 |
| ×倍率相撞 | 150ms 放大到 1.3 倍再回到 1.0 | 回彈 | 小幅震動，強度依分數大小 |
| 金砂流進受器 | 依金量，0.6–2 秒 | 物理流動 | 過金線時：低音＋金線閃 2 次 |
| 第一次發現反應 | 600ms 相撞動畫 | — | 一局內每種反應只播一次 |

- PC 橫屏版（正式版）：燒杯在中央，手牌在左下，元素與受器在右側，同一套圖示。

## 5. 去 AI 感檢查清單

每次交付前逐條打勾。違反任何一條都要修正或在交接檔中說明理由。

### 5.1 文字（含數字與商店文案）
- [ ] 遊戲畫面上沒有任何中英文字（自動檢查見 §8 第 2 項）。
- [ ] 數字只用一種字型（齊線數字），最小 14px，不放在圖片裡縮放，不加外發光。
- [ ] 不同數字有不同的意義色：基礎分墨黑、倍率朱紅、金色只給總分與錢，不再出現其他顏色的數字。
- [ ] 數字不加不必要的小數；大數字用千分位或縮寫（12.4k），不用科學記號。
- [ ] 商店頁與文件不用「踏上旅程」、「解鎖無限可能」、「沉浸式」、「不僅…更是…」等空洞句型；不用一連串破折號。
- [ ] 不用玩家查字典才懂的術語（大業、Nigredo 等）。

### 5.2 UI
- [ ] 沒有毛玻璃（backdrop blur）、沒有到處都是的圓角卡片加陰影。
- [ ] 不用 emoji、不用通用 icon 庫（Material、Font Awesome）；所有圖示自繪，筆寬統一，和銅版刻線同一套畫法。
- [ ] 佈局有主次：燒杯佔 55% 以上，其他元素小而且退到邊緣；不要所有東西都置中對齊、等距排開。
- [ ] 框線用手繪感的刻線（線寬有輕微變化），不用完美的 1px 直線框。
- [ ] 沒有「漸層按鈕」、沒有「hover 時整個發光」。
- [ ] 每個 UI 元件都能回答「它代表杯子裡的什麼東西」；答不出來就刪掉。

### 5.3 配色
- [ ] 只用美術規範的紙色、墨色與 10 個手工上色色票；不用純黑 #000、純白 #fff。
- [ ] 不用紫藍霓虹漸層、不用科技感青色。
- [ ] 高飽和度只留給金與火；其他材料是褪色的手工上色。
- [ ] 背景是有紋理的紙，不是平塗的單色。
- [ ] 色盲模擬（紅綠、藍黃）下，靠形狀仍能分辨每種材料。

### 5.4 動畫
- [ ] 不同事件用不同的時長和曲線（照 §3.3 表），不是全部都是 300ms ease-in-out。
- [ ] 有預備動作和回彈（抬起前先微降，放下時輕彈）。
- [ ] 多個項目依序出現，有錯開，不同時跳出。
- [ ] 閒置時不是所有東西一起上下浮動；只有可互動的物件偶爾、錯開地動一下。
- [ ] 沒有通用的彩色紙屑或星星爆炸特效；特效來自落沙模擬本身（真的煙、真的火、真的金砂）。
- [ ] 震動強度與分數成比例，小事件不震。

## 6. 與目前 v0.2 的差距（提醒實作代理）
- v0.2 的帳本卡、「師父批注」、秘方名稱、商店說明都是文字 → 全部移除，改用 §2 的圖示與 §3 的預覽。
- v0.2 是橫屏 1920×1080 → 改成直屏，但模擬網格維持 160×128（直屏時杯子寬度約 390px，每格 2.4px；**假設**刻線還看得清楚，否則網格改為 128×160 直立）。

## 7. Unity 版與原型的差距（回應 HSU 第 7 點，簡述）
- Unity 專案目前只有 v0.1 的部分架構；所有 v0.2 以後的規則和 UI 都只在瀏覽器原型裡。
- 策略維持「瀏覽器原型先驗證玩法與 UI，確定後再一次移植」，因為瀏覽器原型能讓 HSU 在手機上直接試玩，而且雲端代理可以用 Playwright 自己測試。

## 8. v0.3a「直屏無文字原型」實作清單

給下一個實作代理。範圍是一次完成。基礎是 `prototype/web/`（`template.html` + `sim.js`，用 `build.py` 產生 `index.html`）。**不動 sim.js 的反應規則**，只改呈現與輸入；構築機制（地層、符文、瓶性）留給 v0.3b（見 `DEPTH_v1.md` §6）。

| # | 項目 | 驗收標準 |
|---|---|---|
| 1 | **直屏佈局** | 390×844 與 360×640 兩種視窗：無捲軸；燒杯佔畫面高度 ≥ 50%；手牌每瓶寬 ≥ 72px；所有按鈕 ≥ 44×44px。1920×1080 時以直屏欄位置中（兩側紙紋背景）。 |
| 2 | **移除所有文字**＋自動檢查 | Playwright 腳本在遊戲中、商店、結算三個畫面執行：`document.body.innerText` 去掉空白後只能包含 `0-9 × + − - = / % . , k`；canvas 的 `fillText` 包一層檢查，傳入非數字字元就在 console 報錯。三個畫面 console 無錯誤。 |
| 3 | **材料與反應圖示** | 10 種手牌材料各有瓶身輪廓＋符號（§2.1），16 種反應各有結果符號（§2.2），全部用 canvas／SVG 自繪，不用 emoji 與字型符號。驗收：輸出一張 `docs/art/icons_v03.png` 圖示總表，在灰階下每個圖示仍可區分。 |
| 4 | **拖曳倒料＋ghost 預覽** | 觸控與滑鼠都可以把瓶子拖到杯上；拖曳時出現落點柱與最多 3 個反應結果符號（§3.1），預覽畫在手指上方 ≥ 60px。驗收：截圖顯示「拿著熔岩停在水面上方」時出現石塊與蒸氣符號。 |
| 5 | **火柴與蓋子的預覽** | 火柴模式下會被點燃的格子有暖色輪廓；蓋子 hover 時壓力錶出現虛線指針。驗收：兩張截圖。 |
| 6 | **計分動畫照計算順序** | 反應符號就地浮起（同位置同種合併），基礎分飛向右側元素欄，與 ×倍率相撞變成金色總分，再化成金砂流進受器；過金線時金線閃 2 次。時長照 §3.3。驗收：錄一段 GIF 或連續 6 張截圖。 |
| 7 | **無字教學（第 1 回合三拍）** | §2.5 的示範手、落點柱、火柴晃動；玩家 4 秒無動作才出現示範手；三拍都做對才結束。驗收：Playwright 角色「完全照示範」與「完全不動 10 秒」各跑一次，前者過第 1 回合，後者看得到示範手（截圖）。 |
| 8 | **去 AI 感自檢＋試玩紀錄** | 逐條勾選 §5 清單，結果寫進 `docs/design/playtest_log_v03.md`；自己用 390×844 試玩、找問題、修正至少一輪；`node prototype/web/bot.js 30` 第 1 回合通過率不低於 v0.2（照教學 100%）。 |

## 1. 診斷：v1 為什麼「缺乏創新與行銷價值」

老實說，v1 的問題出在概念本身，數值和美術是次要的。我們從市場研究抄來「熟悉的玩具 + roguelike 成長」這個公式，卻把落沙當成**骰子**：玩家選一瓶倒下去，模擬隨機生出一堆反應，再丟進 Balatro 的 chips × mult 換成分數。這樣一來，模擬只是產生數字的黑盒子。分數來自抽象公式，畫面上的物理事件跟分數沒有對應，所以 HSU 才會「看不出分數怎麼來」。倒完只能等它停下才能算分，所以會拖。玩家能做的只有「選哪瓶、倒哪裡」，倒下去之後就只能看，跟 Powder Toy 比起來反而少了玩具的自由，跟 Balatro 比又少了牌型可以盤算。行銷上我們寫的鉤子本來就是「Balatro，但……」，這是一句 A + B，沒有一個畫面、一個處境能讓人想點進去。霓虹、發光、CRT 是 2024 年後 Balatro-like 的預設外觀，看起來就像什麼都沒決定過，加上通用的瓶罐圖示，AI 感就是這樣來的。**結論：下一版要讓物理本身就是目標和分數**，要「有東西會被保住或被沖走」，讓玩家在模擬流動的過程中一直動手介入，不能只倒完旁觀。

v1 留下的資產：決定性 CA 引擎（`prototype/web/sim.js`）、bot 平衡模擬的作法、低文字量。三個方向都沿用這些。

## 2. 三個新方向

三個方向在**視角、核心動詞、類型**上刻意拉開差距：
- A 是側視的即時防守：把威脅變成建材。
- B 是側視的流體機械：自己搭一台分選機。
- C 是俯視的戰略圍堵：跟風對賭。

### 方向 A：《Ashfall Village》熔岩村（暫名）

**鉤子**：「火山就在你的村子頭上噴發——熔岩一冷，就是你的城牆。」

**處境與核心動詞**：側視剖面，山坡上有一座程序生成的村子，山頂是火山口。熔岩一波一波持續往下流。玩家的動詞是**挖、澆、堵**：
- 左鍵拖曳：挖開地形，造出導流溝。
- 右鍵：從水塔潑水。熔岩碰到水會立刻凝成黑曜石，**這塊石頭馬上就是新的牆**。
- 滾輪：放沙包或石塊（有庫存限制）。

**每秒鐘在做什麼**：看熔岩的流向（流得快的地方亮度高）→ 在它前面兩三格挖溝或潑水 → 剛凝結的石頭改變流向 → 接著處理下一股。熔岩不會停，也沒有「等它靜止」的時刻。噴發的間隔是 20–40 秒的喘息期，玩家可以重建、加蓋房子。

**計分/目標的因果**：
- 每棟房子就是血量。熔岩一碰到，房子當場燒成剪影，就地彈出「−1 戶」。
- 收入是**看得見的物理**：熔岩流進「鍛爐溝」就產出金屬錠，一錠一錠滾進倉庫；火山灰落在田上，作物肉眼可見地長高。
- 風險與報酬也在畫面上：越靠近火山口的田越肥沃，賺越多，也越危險。

**短影音高潮**：
- 熔岩衝破最後一道牆，整排房子連鎖起火。
- 最後一秒潑水，熔岩被逼著繞過教堂。
- 熔岩被導進海裡，炸出巨大的蒸氣雲。

**美術方向（像真人設計的理由）**：**日本新版畫/木版畫**（葛飾北斋《富嶽三十六景》、川瀨巴水的套色版畫）。
- 實作：每種材料只用 1 個「墨版顏色」，全畫面限 6–7 色。材料邊界用 1px keyline 描邊。天空用 bokashi 漸層。疊一層程序生成的和紙纖維雜訊。每個色版**刻意錯位 1px（套色不準）**。這些都是後處理 shader 加調色盤 LUT 就做得到的。
- 套色錯位和紙紋是「印刷的物理缺陷」，看起來像有人刻意做出來的，跟 AI 圖的平滑漸層正好相反。
- 遊戲參考：Pentiment 的木刻插畫段落、Ōkami（墨繪）證明這類風格在遊戲裡可讀。
- 字型用 OFL 授權（Noto Serif CJK 等）。

**能力契合**：沒有角色，村民只是一個點（像 Mini Metro 的乘客）。熔岩是 v1 引擎已有的 LAVA 加上黏度參數。地形是程序生成的。操作是滑鼠「神之手」，不需要動作手感。
- 弱點：即時壓力的難度曲線要靠大量試玩調整。

**市場契合**：
- 類型落在 Survival / City Builder-lite / Strategy / Physics / Roguelite。Zukowski 的資料裡 City Builder 2025 命中率只有 0.5%，塔防也在下層，所以必須包裝成「生存建造」，不能說成塔防。
- 定價 $7.99。文字極少，10+ 語言成本低。
- 試玩版 = 第一座火山 3 次噴發。

**深度來源（30 分鐘之後還在學什麼）**：
- 熔岩的黏度和溫度：冷熔岩會結殼，殼下的岩漿管還在流（真實的熔岩管現象）。
- 學會「用第一波熔岩替第二波蓋牆」的預鋪。
- 火山種類：盾狀火山流得慢量大；成層火山會噴火山彈。
- 建築的相鄰協同。

**Roguelite 結構**：
- 一局 = 一座島嶼上的 3 座火山（ante），每座火山 3 次噴發，最後是 Boss 噴發（火山碎屑流、熔岩湖潰堤）。
- 噴發間的「村議會」從 3 張卡中選 1：新建築、新工具、改寫規則的「地脈」遺物，例如「黑曜石牆耐久 ×2」「熔岩流經田地時施肥」。
- Meta 進度：橫向解鎖新島嶼和新火山類型。

### 方向 B：《Paydirt Sluice》淘金槽（暫名，見 §3 撞名問題）

**鉤子**：「一整座山的泥倒進你的木槽，只有金子會留下來——留不住的，你會看著它流進河裡。」

**處境與核心動詞**：側視，單一畫面。左上是投料斗，中間是一條傾斜的木製淘金槽（sluice），槽底排著擋條（riffle），右下是河。動詞是**調流、擺位、投料**：
- 滾輪：調水閥。水越大，處理量越大，但細金也越容易被沖走。
- 拖曳槽尾把手：調整傾角。
- 右鍵拖曳：在流動中移動或加裝擋條、篩網、磁鐵。
- 左鍵：在投料斗的某個位置倒下一桶泥（paydirt），倒的位置會影響泥在槽裡怎麼攤開。
- 空白鍵：敲碎卡在槽裡的黏土球。黏土球會把金子包著一起沖走。

**每秒鐘在做什麼**：盯著泥流，看哪裡在淤積、哪裡出現金色亮點被帶過擋條 → 微調水量和角度 → 把擋條挪到渦流處 → 敲開黏土球 → 倒下一桶。一天 90 秒，流動從頭到尾不停。

**計分/目標的因果（這是 B 最強的地方）**：
- **金子是全畫面唯一有顏色的東西**（見美術）。分數就是金子本身：被擋條攔下的金粒留在槽裡閃光。
- 每天結束是 3 秒的「清槽揭曉」：掀起擋條，金子滑進右側的玻璃罐，叮叮噹噹地累加，罐子是實體的，會真的被填滿。
- 流失的金子從槽尾飛出時，就地彈出**紅色的「−$0.40」**，HUD 有一個「今天流進河裡：$12.80」計數器。
- 每條擋條上方顯示自己今天攔下多少。「為什麼得分、為什麼虧」都在發生的那一格就看得到。

**短影音高潮**：
- 黏土球被敲開，一顆拇指大的金塊滾出來，「咚」一聲卡進擋條。
- 水開太大，整槽細金像流星雨一樣沖進河裡。
- 清槽揭曉：滿槽黑沙被沖開，底下鋪滿金色。真實淘金頻道的影片也都以 clean-out 揭曉為高潮（**假設**：這是觀察 YouTube 淘金頻道的常見結構，沒有量化數據）。

**美術方向（像真人設計的理由）**：**19 世紀報紙木口木刻 / 銅版線刻**（1890 年代 Harper's Weekly 的淘金熱插畫、Gustave Doré），以 **Return of the Obra Dinn**（Lucas Pope，1-bit 抖動）為遊戲參考。
- 實作：每種材料對應一種**刻線紋理**：水是水平細線，石英砂是點刻，黑沙是密集交叉線，黏土是斜線，岩石是輪廓加陰影線。shader 用材料 ID 查紋理圖塊，再疊一層程序生成的紙張纖維和油墨暈染。
- **唯一的色彩是金色**（帶閃爍的 sparkle shader）。這個限制同時解決「AI 感」和「因果可讀性」：玩家永遠知道金子在哪裡。
- UI 用 OFL 字型 IM Fell（以 17 世紀 Fell 鉛字為本）和 Noto Serif CJK。框線用維多利亞式裝飾邊框，程式繪製。
- 可行性：19 世紀插畫多已進入公有領域，可以當背景和 UI 參考，甚至直接使用。**假設**：要由 art-direction 確認來源館藏（例如美國國會圖書館）的授權標示後，才能加進 `03_assets_legal.md` 白名單。

**能力契合**：
- 分選是**只有粒子模擬才做得到的機制**：不同密度與粒徑的顆粒在水流中自動分層（金 19.3、磁鐵礦黑沙約 5.2、石英 2.65 g/cm³，都是真實數值）。這正好是我們的模擬強項。
- bot 可以直接量測「金回收率」，平衡模擬容易做。
- 沒有角色、沒有動作手感，單一畫面，範圍小。

**市場契合**：
- 類型落在 Automation / Resource Management / Simulation / Physics / Roguelite / Mining。研究裡 Automation 命中率 13.6%、Resource Management 19.5%，Zukowski 也把 mining loop 列為小團隊推薦類型。
- 淘金題材的需求有證據：Hydroneer 28,626 則評論、Gold Mining Simulator 16,440 則、Alaska Gold Fever 1,095 則（2026）。但這三款都是 3D 經營，沒有一款是「物理分選」。
- 標籤鄰居可以吃到 Sandustry（5,674 則）的推薦流量。
- 定價 $7.99。文字極少。簡中市場可以做「金瓜石/九份」河流關卡作為在地化彩蛋（**假設**：要確認史實與敏感度）。
- 試玩版 = 第一條河 5 天，加一個無盡模式排行榜。

**深度來源（30 分鐘之後還在學什麼）**：
1. **流量和回收率的取捨**：每桶泥的成分不同（細金多 → 水要小；大石多 → 要篩網和大水），沒有一組設定永遠最好。
2. **擋條間距與渦流**：擋條後方的低速區才會沉積，玩家會學著「讀水」。
3. **干擾物**：黑沙會跟金子搶擋條空間（磁鐵可以吸走），黏土球會包著金子跑，浮在表面張力上的麵粉金需要「肥皂」工具。這些是真實淘金的現象。
4. **機台組合**：篩網（grizzly）、毛毯（miner's moss）、匈牙利擋條、搖床、滾筒篩，組成多段分選線。後期是**半自動化**：前段機器自動跑，玩家只處理最難的段落，從「手調」自然走到「設計產線」。
5. **風險工具**：水銀汞齊（回收率暴增，但每用一次河流「汙染值」上升，下游的河會變差），這是推運氣的選擇。

**Roguelite 結構**：
- 一局 = 一個淘金季，沿著一條程序生成的河往上游走，3 段河 × 4 天，最後一天是 Boss 日（山洪、結冰、搶礦者截流）。
- 每天傍晚要繳**礦區租金**，金額逐日上升（Luck be a Landlord / CloverPit 式的壓力），繳不出來這局就結束。
- 雜貨店的商品有三類：
  - 「泥桶」：等於牌組，可以挑成分已知的礦點泥。
  - 「機件」：等於可以擺在槽上的遺物，槽上有空間上限，所以是**空間型 build**，類似 Backpack Hero 的取捨。
  - 「規則改寫」：例如「黑沙也算錢」「每撿到一顆金塊，水閥自動調小」。
- 路線分岔：上游金粒大但石頭多，下游是細金加大水。
- Meta 進度：橫向解鎖新河流（Klondike、California、Otago、Ural……）和新機件，不給永久數值加成。

### 方向 C：《Red Line》野火線（暫名）

**鉤子**：「從高空看一場正在吃掉山谷的野火——你畫的每一條線，都在跟風對賭。」

**處境與核心動詞**：俯視地形圖，火從一個點開始，依燃料（草、灌木、針葉林）、坡度和風向蔓延，跑在 CA 上。動詞是**畫線、投放、回燒**：
- 左鍵畫防火線：推土機沿線慢慢推進，需要時間。
- 右鍵：指定空投水的位置，有冷卻時間。
- 拖曳：點燃回燒，用小火吃掉大火前方的燃料。
- 空白鍵：0.25 倍慢動作。只是放慢，不會暫停。

**每秒鐘在做什麼**：讀風向箭頭和火線前緣 → 決定這一條線要畫在哪裡、能不能在火到之前完成 → 投水拖延 → 風向轉了，馬上改線。

**計分/目標的因果**：
- 被保住的林地與聚落面積就是分數，用即時的「保全率 %」顯示。
- 燒掉的區塊永久變成灰色的影線，一眼就看得出哪條線失守、從哪裡失守。

**短影音高潮**：
- 火越過山脊，一口氣吞掉整片針葉林。
- 回燒的火和主火正面相撞，兩邊同時熄滅。

**美術方向**：USGS 地形圖 / 瑞士 Imhof 暈渲地圖 + 真實火場「incident map」的手繪紅色火線，參考 Mini Metro 的地圖抽象化。
- 等高線用 heightmap 的 `fract()` 加 `fwidth` 生成，燃料用製圖影線表示。全部 shader 化，非常像真人設計。

**能力契合**：完全契合，CA、地形生成、shader 都是強項。

**市場契合**：
- Strategy / RTS-sim / Simulation，比 A、B 更小眾。
- **競品在 2026–27 年突然變多**（見 §3），新穎度最低。

**深度與 roguelite**：
- 深度來自燃料、坡度和風的組合，加上回燒時機。
- 一局 = 一個火季，連續多場火災，前一場的燒跡會成為下一場的天然防火帶。
- 局間升級是器材與人員卡。

## 4. 評分矩陣與推薦

1–5 分；權重加總 100。

| 準則（權重） | A 熔岩村 | B 淘金槽 | C 野火線 |
|---|---|---|---|
| 鉤子與短影音高潮（20） | **5** | 4 | 4 |
| 解決回饋：因果一眼懂、流動不等待（15） | 4 | **5** | 4 |
| 契合能力（模擬/程序/shader，無角色手感）（15） | 4 | **5** | **5** |
| 美術可行且「像真人設計」（10） | 4 | **5** | **5** |
| 類型市場表現（15） | 3 | **4** | 3 |
| 新穎、未飽和（15） | **4** | **4** | 2 |
| 範圍風險低（2–3 人月可做出 Demo）（10） | 3 | **4** | **4** |
| **加權總分** | 3.95 | **4.40** | 3.80 |

（算法：Σ 分數 × 權重 ÷ 100。A = 100+60+60+40+45+60+30 = 395；B = 80+75+75+50+60+60+40 = 440；C = 80+60+75+50+45+30+40 = 380。）

### 推薦：方向 B「淘金槽」

理由：
1. **物理就是分數**。v1 的病根是模擬和分數脫鉤；B 的分數就是畫面上被留住的那些金粒，流失也是當場看得到的紅字。HSU 的第一大回饋從結構上就消失了。
2. **流動不停、介入不停**。水閥、角度、擋條、敲黏土都是在流動中做的，沒有「等它停」的時刻。
3. **「只有落沙模擬才能做」的機制**：依密度分層是我們的技術護城河，3D 經營類的淘金遊戲做不出這種畫面。
4. **類型對**：Automation / Resource Management 是研究中命中率最高的一群，淘金題材也有 Hydroneer、Gold Mining Simulator 等需求證據。
5. **美術限制剛好同時解決兩個問題**：1-bit 刻版線條讓畫面不像 AI 圖，「唯一有顏色的是金子」又讓可讀性變好。

A 熔岩村的鉤子最強，當作**備案**：如果 B 的原型證明水流分選做不出手感，A 可以沿用同一套流體引擎，物理要求也比較粗。C 因為競品突然變多，不建議。

## 5. 下一個可玩原型（方向 B）

### 要驗證的 3 個假設
1. **H1 技巧有意義（bot 可量測）**：調整水量、角度、擋條位置，「最佳設定 bot」的金回收率至少是「隨機設定 bot」的 2 倍；而且不同成分的泥桶最佳設定不同（最佳水量至少有 3 個不同的 bin）。如果 < 1.3 倍，或某一組設定永遠最好 → 分選沒有深度，改走 A。
2. **H2 因果可讀、沒有等待**：HSU 不看說明玩完 1 天（90 秒）後，能自己說出「金子為什麼流失」並主動改設定（目標：第 2 天回收率提高）。遙測顯示「沒有任何輸入的連續 ≥3 秒」次數每天 ≤ 2 次（清槽揭曉除外）。
3. **H3 想再玩、看起來像人做的**：玩完 3 天後 HSU 會自願再開一局。清槽揭曉或金塊時刻被他指認為「最爽的一刻」。刻版加金色的畫面沒有被評為 AI 感。另外做一支 10 秒無聲 GIF，給 HSU 憑第一印象說「這是什麼遊戲、想不想玩」。

### 最小原型範圍（2–3 天，瀏覽器版，沿用 `prototype/web/` 的作法）
- **第 1 天：模擬**
  - 新檔 `prototype/web/sluice_sim.js`（決定性，可以用 node 跑）。
  - 網格 192×108，6 種材料：水、石英砂、黑沙、黏土球（內含金）、礫石、金（片金是單格；金塊先用 2×2 剛體近似）。
  - **水帶水平速度欄位**：沉積物被水帶走的機率 ∝ 流速 ÷ ((密度 − 1) × 粒徑)。擋條後方是低速區，顆粒會沉降。這是唯一新的技術點，也是最大風險，先在 node 裡用 bot 跑 H1。
- **第 2 天：操作與 UI**
  - 滾輪調水閥、拖曳調傾角（-4° 到 -15°）、右鍵拖曳 4 條擋條、左鍵在 3 個投料位置選一個倒泥、空白鍵敲黏土。
  - 金流失時在槽尾就地彈出紅字，HUD 顯示「今日流失」；擋條上顯示攔截數；右側玻璃罐實體累積金粒。
  - 每天 90 秒，結束後清槽揭曉 3 秒（可跳過）。
- **第 3 天：結構與外觀**
  - 3 天制，租金逐日上升（例：$20 / $35 / $55，之後由 bot 調）。
  - 商店每天 3 選 1：匈牙利擋條、磁鐵（吸黑沙）、篩網（擋礫石）。每天的泥桶有 2 種成分可選。
  - 刻版風用 canvas 逐像素材料紋理查表（Bayer/刻線圖塊）加紙紋，金色加 sparkle。
  - bot：隨機 vs 網格搜尋最佳設定，報告寫到 `docs/design/balance/`。
- **不做**：音效、meta 進度、路線圖、Boss 日、在地化、Unity 移植。

### 最大風險
**沉積物被水帶走的物理是否「看起來對、玩起來有手感」**。CA 的水沒有動量，金子要沉、沙要被沖走，都必須加一個簡化的流速場。萬一流速場不穩定（抖動、顆粒卡死），分選看起來就是隨機的，H1、H2 都會失敗。對策：第 1 天先只做模擬加 bot，H1 沒過就不做 UI，直接改做 A 的原型。

次要風險：「淘金」的題材張力可能不如熔岩，短影音的點擊率不確定。用 H3 的 10 秒 GIF 測第一印象；上商店頁前可以拿 A、B 的 GIF 一起給 HSU 盲選。
